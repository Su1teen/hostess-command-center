## Local evidence and reproduction

Use Node 22+ and Bun 1.3.13. Set `TEST_DATABASE_URL` to a disposable loopback PostgreSQL database owned by `hostess_test`. The integration runner uses unique schemas and removes them. Commands: `npm run typecheck`, `npm run lint`, `npm run test:unit`, `npm run test:integration`, `npm run build`, `node scripts/test-ui.mjs`.

The PostgreSQL acceptance run includes 35 booking tests; 53 passing dining tests (one optional sibling-source check is skipped by the Windows Node adapter); 10 physical inventory tests; 15 floor operations tests; migration clean install/replay with unchanged 17 QR credentials. The real paired HTTP/browser test separately validates the actual current Hostess consumer. Unit tests: 41. Historical snapshot immutability, repeated checkout, access control, holds, WhatsApp source, version conflicts, partial/failing outbox delivery and compensation remain tested alongside new scenarios.

`npm run test:cross` requires `XOXO_SOURCE_ROOT`, `HOSTESS_SOURCE_ROOT`, and two empty disposable loopback databases `CROSS_RECEIVER_DATABASE_URL` / `CROSS_SENDER_DATABASE_URL`. It starts the actual XOXO Prisma application, Command Center handler, Hostess BFF and a real HTTPS guest browser. Six canonical orders result in twelve delivered accepted/cancelled events, retry creates no second sale, ordinary menu creates no Exchange demand, final demand is zero after compensation, and published price history is unchanged. The browser completes anonymous website checkout and sees staff acceptance in the same receipt. It imports/repeats all 119 official ordinary variants and compares every BFF price.

The staff browser suite covers mixed order details, persistent publication, full menu import, bulk stop/restore, inline pricing, guest management, registry and exports with unchanged credentials, QR/booking independence, seating, per-visit folio isolation, manual and WhatsApp bookings, 17:00 versus 19:00 timeline, layout editing, real two-touch pinch gesture and scrolling. It verifies in-context staff checkout/payment, inline seating with NULL capacity/pending attestation/QR disabled, operator cancellation, and outbox recovery after restart without incoming requests. Chromium widths are 320/375/390/430/768/1024/1440; WebKit provides a separate mobile smoke.

Screenshots and QR export PDFs are emitted under `test-results` and uploaded by CI. The guest fixture suite is clearly separate from real cross-service evidence. No production test guest/order/payment/bonus is created.

## Release and recovery

Migrations 0012–0014 are additive or replace existing guard functions; no table, QR credential, zone, layout, accepted order or ledger row is removed. Startup applies them under the existing migration advisory lock before accepting requests. Capture a native database-volume backup and immutable QR fingerprint before merging. Merge backend first, verify `/health` and migration ledger, import reviewed menu, then merge frontend and verify the Cloudflare `x-hostess-build` response header against its merge SHA. Check every imported price/photo and all existing QR contexts read-only.

If application rollback is necessary, redeploy the previous application build. Additive quote/provenance/preorder columns are backward compatible and should be retained. Do not blindly drop new columns, reverse operational bookability or restore a volume over newer guest transactions. Restore a snapshot only as an explicitly coordinated incident action.
