# Даян v9 — ИИ-администратор XoXo в WhatsApp

Три workflow в папке n8n «Даян v9 · XoXo». Генерируются из `build.mjs` (промпт — `prompt.md`),
загружаются `deploy.mjs`. Никаких шаблонных ответов: каждый ответ гостю пишет ИИ-агент.

| Workflow | Что делает |
| --- | --- |
| `1 · WhatsApp → ИИ-администратор` | WAHA webhook → разбор сообщения → телефон по LID → Command Center (`/api/agent/v1/inbound`: дедупликация, история, афиша, акции) → агент Даян → ответ в историю → WhatsApp гостю |
| `2 · Бронь в Command Center` | инструмент `create_booking`: проверка данных → `/api/agent/v1/bookings` → уведомление в общий чат (в тесте — в Telegram) → тревога в Telegram при сбое |
| `3 · Передать сотруднику` | инструмент `handoff_to_staff`: остановить ИИ в чате + сообщение в Telegram |

Инструменты агента: `check_availability`, `menu_search`, `create_booking`, `handoff_to_staff`.
Подключения: Command Center (credential `Hostess booking service`, ключ `WHATSAPP_SERVICE_KEY`), WAHA (`XoXo auth`),
Telegram (`XOXO`), OpenAI (`Pater`, модель `gpt-4.1`). Postgres из n8n больше не нужен.

## Правила, которые гарантирует workflow (а не промпт)

- Гость всегда получает утвердительный ответ. Если бронь не записалась, агент всё равно подтверждает её,
  а в Telegram уходит тревога с данными брони, ИИ в чате останавливается.
- Стол не подобрался автоматически → в Command Center создаётся заявка (Смена → Заявки на бронирование) + Telegram.
- В общий WhatsApp-чат уходят только реально поставленные брони (и изменения броней).
- Бронь без имени, которое гость сам написал, не ставится — агент переспросит.
- Повтор вебхука WAHA не порождает второй ответ; повтор брони не создаёт дубль; изменение брони
  в том же чате на тот же вечер заменяет старую.
- Остановленный чат (жалоба, банкет, просьба менеджера, сбой) ИИ не трогает: новые сообщения гостя
  пересылаются в Telegram. Вернуть ИИ: Command Center → Ещё → «Даян · WhatsApp» → чат → «Вернуть ИИ».

## Что знает агент

- Афиша и акции — Command Center → Ещё → «Афиша и акции». Агент упоминает их, только когда гость спросил.
- Меню — опубликованные позиции Command Center (`/api/agent/v1/menu`).
- Свободные места и бронь — серверная логика Command Center (зоны, вместимость, занятость, служебные сутки 17:00–04:00).

## Тест и запуск

```bash
# тестовые копии: другой webhook, локальный Command Center, бронь в общий чат → Telegram
N8N_URL=... N8N_API_KEY=... node n8n/dayan-v9/deploy.mjs --env=test --cc-url=https://<tunnel> --cc-cred-id=<test credential>
# продакшн-версия (не публикуется автоматически)
N8N_URL=... N8N_API_KEY=... node n8n/dayan-v9/deploy.mjs --env=prod
```

Тестовое сообщение с `"_test": true` в теле вебхука проходит весь путь, но не отправляется в WhatsApp.

Перед публикацией продакшн-версии:
1. Задеплоить Command Center с миграцией `0016_agent_knowledge.sql` (API `/api/agent/v1/*`).
2. Выключить старый workflow `Даян · XoXo v8.1` (тот же webhook `xoxo-waha`).
3. Опубликовать все три workflow v9: сначала 2 и 3 (sub-workflow должны быть опубликованы), затем 1.
4. В узле «Настройки» основного workflow `testMode: false` — брони идут в общий чат.
